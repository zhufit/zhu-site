## 内容与判定

临时发布文章和精选项目，覆盖长中文标题、连续英文、长标签/技术栈、中文长文、Java/Shell/JSON 代码、六列表格以及 2400×900 SVG 架构示意图。检查 Header、Hero、列表、详情、正文、元信息和 Footer；图片完成加载后再判定尺寸。

自动检查实际 innerWidth、文档 scrollWidth、普通元素边界、图片尺寸及代码/表格滚动区域。不使用 overflow-x:hidden 掩盖页面问题。代码和宽表格可在自己的区域滚动，内部超宽内容不作为页面溢出失败。截图包含首屏与完整页面，便于观察正文、图片及页尾。

初次检查发现文章 Header 隐式网格列被长英文标题撑宽，已将列改为 minmax(0, 1fr)，并添加 overflow-wrap:anywhere。修复后全部视口通过，文章布局回归测试通过。

## 复跑

```bash
python3 tools/check-responsive.py
```

要求已安装项目依赖、Python 3、Node ≥22.12 和 Chrome。默认使用 macOS 的 Google Chrome 路径；其他系统通过 RESPONSIVE_CHROME 环境变量指定浏览器可执行文件。检查需要本机监听端口与启动无界面 Chrome 的权限，不安装额外 Python 或 npm 依赖。

脚本创建临时内容、构建并向构建页插入诊断脚本，通过 tools/responsive-browser.mjs 设置精确视口。完成后停止临时服务器及独立 Chrome 进程，删除临时内容，再构建恢复生产输出；运行失败同样执行恢复。不要与其他修改内容目录或 dist 的测试同时运行。

终端打印结果目录，包含 results.json、各页面完整截图和带 -top 后缀的首屏截图。结果保存在系统临时目录，不纳入站点产物；生产页面不包含诊断脚本。

本次覆盖 Chrome 的六个指定视口。后续更改字体、导航、组件或导入实际照片后应重新检查；Safari、Firefox 和真实触摸设备行为尚未单独验收。
